# Мала матура — историја

Дигитална припрема за завршни испит: ученик вежба на телефону, одмах види где
греши и зашто. Уз то, апликација је инструмент докторског истраживања
ретенције знања (фазе T0–T3, форме A/B/C, телеметрија, псеудонимизовани CSV).

Садржај: **120 задатака из збирке за завршни испит (ЗВКОВ, 2025/2026), део
ИСТОРИЈА, задаци 241–360**. Тачни одговори су искључиво из одељка РЕШЕЊА
(стр. 174–179), никад из обојених кружића у попуњеном примерку збирке.

Правила рада на коду су у `../CLAUDE.md` — прочитати пре сваке измене.

```
mala-matura/
  server/   Express 5 + Drizzle; PostgreSQL или уграђени PGlite; тестови (vitest)
    data/istorija.json   почетни садржај (задаци, кључ, објашњења)
    data/images/         карте, фотографије, графикони (иду у базу)
  client/   React 19 + Vite + Tailwind; мобилни приказ од 320px
```

## Покретање на свом рачунару

Не треба инсталирати базу: без `DATABASE_URL` сервер диже уграђени PGlite
(Postgres у самом процесу) у `server/.data/pglite`.

```bash
cd mala-matura/server
npm install
cp .env.example .env      # упиши ADMIN_USERNAME, ADMIN_PASSWORD (бар 8 знакова)
npm run seed              # админ налог + 120 задатака + слике
npm run dev               # http://localhost:3001

cd ../client
npm install
npm run dev               # http://localhost:5173 (прослеђује /api на 3001)
```

`npm run seed` само **убацује оно чега нема**: постојећи налог (ни лозинку),
задатак, слику или форму не дира. Док ради `npm run dev`, seed одбија да ради
над PGlite базом (два процеса би је оштетила) — прво заустави сервер.

Изграђена верзија на једној адреси (као на хостингу):

```bash
cd client && npm run build
cd ../server && npm run build && npm start     # http://localhost:3001
```

## Провере пре комита

```bash
cd server && npm test && npm run typecheck      # 63 теста
cd ../client && npm run typecheck
npm audit                                       # у оба пакета — мора бити 0
```

Тестови покривају: бодовање сваког типа (тачан / нетачан / ивични),
нормализацију (латиница → ћирилица), да `correct` и `explanation` не излазе
ни на једној рути пре `/submit` (претрага целог JSON-а), свих 120 задатака из
`data/` (кључ пролази бодовање, промењен одговор не пролази, нема рупа у
бројевима, слике постоје), seed који само убацује, CSV колоне и цео ток кроз
API (вежбање, контролна група, мерење, форме, извоз само уз сагласност).

## Типови задатака

| Тип | У збирци | Одговор ученика | Кључ (`correct`) |
|---|---|---|---|
| `single` | обој кружић испред тачног одговора | број понуђеног одговора | број |
| `multi` | више тачних одговора | низ бројева | низ бројева |
| `text` | „Одговор: ____“ | низ стрингова, по пољу | низ низова прихватљивих облика |
| `matching` | табела „обој кружић у одговарајућем пољу“ | за сваки ред број колоне | низ бројева |
| `ordering` | поређај | бројеви ставки редом | тачан редослед |

Бодовање је само на серверу (`server/src/scoring.ts`), све-или-ништа по
задатку. Упис се пореди после `normalizeText`: мала слова, сажети размаци,
латиница у ћирилицу — „Mesopotamija“ = „Месопотамија“.

Историја користи `single` (89), `text` (15), `matching` (14) и `multi` (2).
Прилагођавања збирке моделу (нпр. задатак 288, 300, 348, 360) и уочене
штампарске грешке (293, 302) записана су у пољу `note` уз задатак у
`data/istorija.json` — то поље се не уписује у базу.

Задаци живе **у бази**: после првог seed-а мењају се само кроз админ
(Админ → Задаци). Свака измена повећава `version`, а верзија се уписује уз
сваки одговор ученика — у подацима се види који облик задатка је решаван.

## Вежбање

Задаци се вежбају по целинама од 20 бројева (241–260 … 341–360), редом као
у збирци, уз стране књиге. Једно питање по екрану; „Провери“ шаље одговор на
`/attempts/:id/questions/:qid/submit` и тек тада стижу кључ и објашњење.
Рачуна се први предати одговор — нема погађања до тачног.

## Истраживање

| | Вежбање (интервенција) | Мерење |
|---|---|---|
| Кад | кад год је вежбање отворено | само кад истраживач отвори термин |
| Повратна информација | одмах, уз објашњење | само резултат, без кључа |
| Покушаја | неограничено | један по фази |
| Контролна група | нема приступ | ради |

**Фазе** T0 → вежбање → T1 → T2 → T3; текућу фазу и термин поставља
истраживач (Админ → Истраживање). **Форме A/B/C** су бројеви задатака из
збирке које бира истраживач — апликација их не прави сама. Ротациона група
(1–3) додељује се аутоматски, у најмању групу:

| Група | T0 | T1 | T2 | T3 |
|---|---|---|---|---|
| 1 | A | B | C | A |
| 2 | B | C | A | B |
| 3 | C | A | B | C |

T0–T2 чине латински квадрат (свака форма у свакој фази), а T3 понавља форму
из T0 — задржавање се мери на истим задацима. Зато се после мерења кључ не
приказује. Кад мерење почне, форме се више не могу мењати.

**Сагласност пре података:** `consent_research` поставља админ ручно, тек уз
потписан образац родитеља/старатеља. Извоз садржи само такве ученике, под
псеудонимом (`RESEARCH_ID_PREFIX` + број, нпр. `IS-0007`), без имена.

## CSV извоз

Админ → Покушаји. Колоне су **исте на свим платформама** (`server/src/csv.ts`)
и не мењају се; тест пада на сваку промену.

| Фајл | Један ред | Колоне |
|---|---|---|
| `pokusaji.csv` | покушај | csv_version, research_id, subject, class_group, study_arm, rotation_group, attempt_id, kind, phase, form, section, started_at, submitted_at, duration_ms, questions_total, questions_answered, correct_count, score, max_score, percentage, mobile |
| `zadaci.csv` | задатак у покушају | csv_version, research_id, subject, attempt_id, kind, phase, form, question_id, question_number, question_version, question_type, position, answered, answer, is_correct, points, max_points, time_ms, changes, answered_at |
| `dogadjaji.csv` | догађај телеметрије | csv_version, research_id, subject, attempt_id, question_id, event, at, value |

BOM на почетку (Excel и ћирилица), водећи `=`, `+`, `-`, `@` неутралисани,
поништени покушаји искључени.

## Постављање (Render)

Један Web Service, Root Directory `mala-matura`, уз Postgres (Render или
Supabase).

- **Build:** `cd client && npm ci --include=dev && npm run build && cd ../server && npm ci --include=dev && npm run build`
- **Start:** `cd server && npm run seed:dist && npm start`
- **Environment:** `NODE_ENV=production`, `DATABASE_URL`, `SESSION_SECRET`
  (дугачак насумичан низ; промена одјављује све), `ADMIN_USERNAME`,
  `ADMIN_PASSWORD`, `RESEARCH_ID_PREFIX`.

Табеле се праве саме при покретању (миграције су идемпотентне). Seed при
сваком покретању само допуњава оно чега нема. Провера: `GET /api/health`.

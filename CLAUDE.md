# Мала матура — упутство за рад на овом репозиторијуму

## Шта је ово

Дигитална **припрема** за малу матуру. Деца вежбају на телефону и одмах виде
где греше. Апликација има и истраживачку инфраструктуру (телеметрија, фазе
T0–T3, форме A/B/C, псеудонимизовани CSV извози) за докторско истраживање
ретенције знања.

**Шта ово НИЈЕ:** генератор тестова. Тестове штампа Министарство и ученици их
полажу на папиру у учионици. Не додавати генерисање или штампу тестова.

Апликација живи у `mala-matura/` (сервер + клијент). Види `mala-matura/README.md`.

## Златна правила — важе за сваку измену, без изузетка

1. **Бодовање само на серверу, увек са тестовима.** `server/src/scoring.ts` је
   ЈЕДИНА функција бодовања. Ниједан тип питања не иде у продукцију без три
   тест случаја: тачан / нетачан / ивични. Тест се пише пре имплементације.
2. **`correct` никад не напушта сервер пре предаје.** Провера руком: F12 →
   Network на рути за питања. Аутоматски: `api.test.ts` претражује цео JSON.
   Тачан одговор и објашњење смеју ка клијенту тек у одговору на `/submit`.
3. **Идентичне CSV колоне на свим платформама.** Дефинисане у `server/src/csv.ts`.
   Не мењати редослед ни називе колона — то је оно што чини датасете спојивим
   без иједног преименовања.
4. **Питања у бази, не у коду.** Садржај се мења кроз админ, код кроз git.
   Никад не уписивати питања у `.ts` датотеке.
5. **Админ лозинка из env варијабле, seed никад не ресетује постојеће.**
   `seed.ts` сме само да убаци што не постоји. Ништа не брише, ништа не преписује.
6. **Сагласност пре података.** `consent_research` је капија за сваки извоз и
   поставља се тек уз потписан образац родитеља/старатеља, ручно кроз админ.

## Команде

```bash
cd mala-matura/server
npm test          # 63 теста — мора бити зелено пре комита
npm run typecheck
npm run seed      # тражи ADMIN_USERNAME и ADMIN_PASSWORD у env
npm run dev       # порт 3001; без DATABASE_URL диже уграђени PGlite

cd mala-matura/client
npm run dev       # порт 5173, прослеђује /api на 3001
npm run build
```

## Мобилни приказ је обавезан, не додатак

Питања су дугачка и сложена, деца их решавају на телефону. Свака измена
интерфејса мора да прође на екрану од 320px (iPhone SE):

- ниједна површина за додир испод 44px, на СВАКОМ типу питања
- без хоризонталног скроловања
- поља за унос 17px или више (испод тога iOS зумира при фокусу)
- натписи дугмади не смеју да се преламају у више редова
- једно питање по екрану, навигација у фиксираној траци при дну

## Језик

Интерфејс, поруке о грешкама и коментари у коду су на **ћирилици**. Називи
променљивих и функција могу бити латиницом кад је то уобичајено (`subjectId`),
али све што ученик или наставник види иде ћирилицом.

Текстуални одговори се нормализују пре поређења (`normalizeText`): trim, мала
слова, сажимање размака и пресловљавање латинице у ћирилицу. Дете које откуца
`Imenica` мора добити исто као оно које откуца `именица`.

## Научене лекције — не понављати

- **Питања типа `ordering` морају да крену измешана.** Ако ставке стоје тачним
  редом, ученик који не додирне ништа добија пуне поене. Затворено на два
  места: админ чува ставке измешане, клијент их и приказује измешано.
- **`scrollIntoView` подвлачи садржај под лепљиво заглавље.** Користити
  `window.scrollTo({ top: 0 })`.
- **drizzle-orm испод 0.45.2 има SQL injection** (GHSA-gpj5-g38j-94v9).
  Држати `npm audit` чистим — ово је апликација са подацима деце.
- **Провера површина за додир мора да иде кроз сваки тип питања**, не само
  кроз први екран. Стрелице за ређање су тако прошле као премале.

## Пре комита

1. `npm test` у `server/` — зелено
2. `npm run typecheck` у оба пакета
3. Ако је дирано питање или бодовање: додати тест за тачан/нетачан/ивични случај
4. Ако је диран интерфејс: проверити на 320px
